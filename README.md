# Yuvraj Skills

Start with [skill-synthesis](skills/skill-synthesis) to choose guidance for a project. Each folder contains a skill entrypoint and its supporting resources. Install individual packages in a skill directory recognized by your agent. Some packages require a specific host, service, or runtime.

## Original workflows and public adaptations

| Skill | Use it to |
| --- | --- |
| [skill-synthesis](skills/skill-synthesis) | Compare skills and primary sources, resolve conflicts, and turn the best ideas into a verified implementation. |
| [prepare-project](skills/prepare-project) | Turn a product idea into a concrete user journey, engineering decisions, and a build plan. |
| [brainstorm-to-frontend](skills/brainstorm-to-frontend) | Hand product decisions to a frontend builder with interactions and acceptance criteria intact. |
| [brainstorm-to-backend](skills/brainstorm-to-backend) | Translate product decisions into backend contracts, state changes, and failure handling. |
| [create-engineering-team](skills/create-engineering-team) | Coordinate engineering ownership, isolated work, review, and integration. |
| [clean-codebase](skills/clean-codebase) | Make a codebase easier to navigate, change, and hand over. |
| [skill-library-maintenance](skills/skill-library-maintenance) | Audit skill inventories, reconcile variants, and verify provider discovery. |
| [frontend-directions](skills/frontend-directions) | Build and compare complete switchable frontends, then combine the strongest ideas. |
| [max-frontend](skills/max-frontend) | Design expressive frontends with cinematic motion and responsive interactions. |
| [mobile-frontend](skills/mobile-frontend) | Design and test thumb-friendly layouts, gestures, and software-keyboard behavior. |
| [invisible-performance](skills/invisible-performance) | Reduce rendering and loading costs while preserving the visible experience. |
| [web-accessibility-quality-audit](skills/web-accessibility-quality-audit) | Audit real user journeys for accessibility barriers and prioritize fixes. |

## Standalone development guides

Written for this collection using generic examples.

| Skill | Purpose |
| --- | --- |
| [deep-review](skills/deep-review) | Review an implementation across its user-visible contract, data flow, and failure paths before integration. |
| [rca](skills/rca) | Investigate an observed failure and identify the earliest causal divergence from expected behavior. |
| [rca-fix](skills/rca-fix) | Turn an established root cause into a narrowly targeted repair and a regression check. |
| [rca-sweep](skills/rca-sweep) | Look for other instances of a confirmed failure mechanism and prioritize the affected paths. |
| [runtime-verify](skills/runtime-verify) | Verify a claimed behavior through the running application and distinguish direct evidence from simulated coverage. |
| [knip](skills/knip) | Investigate unused JavaScript or TypeScript files, exports, and dependencies with Knip. |
| [elysiajs](skills/elysiajs) | Build or review an Elysia HTTP endpoint with explicit input validation, plugin boundaries, and request-level tests. |
| [inspira-ui](skills/inspira-ui) | Integrate an animated Inspira UI component into a Vue or Nuxt application and verify rendering, input, and cleanup. |
| [predictive-maintenance-demo](skills/predictive-maintenance-demo) | Build a simulated predictive-maintenance walkthrough with traceable sensor evidence and verifiable outcomes. |
