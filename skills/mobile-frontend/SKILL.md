# Mobile frontend

Walk through the main task on a narrow screen. Identify what someone needs in thumb reach, what can wait, and what must stay visible while they type. Recompose dense screens around that task. Keep desktop behavior intact when changing shared components.

If a horizontal pager makes related items easier to inspect, use native scrolling and snap points. A swipe, a navigation button, and a direct link should all settle on the same selected item. Expose an equivalent control for people using a keyboard. Keep vertical scrolling available within long items.

Try the page with the software keyboard open. Verify the focused field and submit action remain reachable, including with a short viewport and large text. Return focus after dismissing a sheet. For motion-sensitive users, provide a direct transition to the same state.

Check the journey on touch hardware when available. Report which viewport, input method, and browser you actually exercised. See the [mobile walkthrough](references/walkthrough.md) for a compact example.
